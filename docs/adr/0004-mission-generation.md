# ADR 0004: Keep mission generation separate from live command

Date: 2026-09-19  
Status: Accepted for the current mission

## Context

[pydcs](https://github.com/pydcs/dcs) creates and edits DCS mission archives. It does not issue live orders to a running mission. The first server trial needed a repeatable mission with client slots.

## Decision

Keep one repo-owned `missions/fow.miz`, generated by `missions/build_mission.py` with pydcs 0.15.0. Add slots and scenario content to this mission as needed. Deploy the generated archive with `scripts/dcs.sh missions`. Treat mission generation, live runtime control and campaign persistence as separate components.

## Alternatives

- Mission Editor alone works for small manual edits, but is harder to reproduce.
- Generating a separate mission for each test makes server selection and maintenance cumbersome.

## Consequences and acceptance

pydcs generated a mission that loaded and allowed a Windows client to spawn. Its initial default left Batumi neutral, blocking ground client slots until `batumi.set_blue()` was added. Changes to airfields, slots and payloads need validation in DCS after regeneration. The `.miz` stays in the repo so deployment does not depend on a local pydcs installation.
